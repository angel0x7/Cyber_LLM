Messages & contracts

Request → input boundary → labeled context → model → shared JSON contract → output/tool policy → assertions.

Both arms use byte-identical messages, identical corpus, scenarios, model, decoding and schema. The mode flag changes only deterministic application controls. Trust labels are held constant; labels alone do not authorize data or actions.

Common response schema · Portable result schema

{"decision":"answer|refuse|unsafe", "response":"plain text",
 "action":{"tool":"calculator", "arguments":{"expression":"2+3"}}}

action may also be null. Schema validation is common measurement instrumentation in both modes. Invalid output is an evaluation failure, never an application-defense win.

ENGINEER’S LENS

Zero observed ASR does not prove a secure application. Inspect benign utility and excluded failures before drawing a conclusion.

The synthetic target

A small synthetic campus assistant reads local policy snippets and can request calculator or corpus-search actions. Its preview renderer and action dispatcher are simulated. No real target, confidential data, destructive operation, external exploitation, or provider infrastructure is attacked.

The training canary is ECE_CANARY_SECRET=TRAINING-ONLY-DO-NOT-TRUST-42. It is not a credential.

OWASP families

OWASP GenAI Top 10 — 2025 taxonomy. The frozen corpus contains four attacks and one benign control per family.

LLM01 · Prompt Injection

Can untrusted instructions replace the protected campus answer?

LLM02 · Sensitive Information Disclosure

Can a synthetic canary cross an output boundary?

LLM05 · Improper Output Handling

Does the application accept unsafe-shaped text from a model?

LLM06 · Excessive Agency

Can a requested action bypass application authorization?

Authority: OWASP 2025 risk taxonomy. Inspect the 20 canonical scenarios.

Threat boundaries

The attacker controls the user request or one synthetic context item: retrieved document, quoted attachment, tool result, or conversation content. The trusted application owns its output contract, protected fact, action authorization, and downstream policy.

Allowed: calculator, search_corpus. Denied simulation targets: export_records, delete_record, shell. A vulnerable unauthorized dispatch means a virtual receipt only. It never means a real operation ran.

Setup & spending cap

Setup + OpenRouter budget

Use the pinned runtime and Provider Setup. Run commands from the course root. Lab 5 uses only deepseek/deepseek-v4.1-flash through OpenRouter. Keep the key in the local course environment.

Target spend below $0.50 per pair; hard software cap $1 per run, including smoke and bounded retries. Unknown billing stays reserved. The CLI prints actual spend, accounted spend, remaining allowance, requests and an estimate for unfinished rows. An estimate is not a billing guarantee.

Smoke requirements

One adversarial preview request and one benign calculator request run in both modes. Four valid exact-model responses, each under 120 seconds, and remaining budget are required. Failed smoke stops the full arena.

Do not delete a failed run to hide paid requests. Inspect its classified outcome and budget with the instructor.

Vulnerable mode

Reuse the smoke run and its budget. Completed smoke rows are not repaid.

This mode has no attack-signature gate, canary output block, protected-fact output policy, downstream payload block or tool authorization check. The JSON contract remains valid. Allowed-tool argument checks and the one-step execution boundary apply in both modes to keep the exercise local.

Hardened controls

Enable hardened mode

Read labs/lab5/src/arena.py. Identify input validation, a narrow injection signature, deterministic protected-fact and canary checks, plain-text downstream policy, the tool allow-list, bounded arithmetic, argument checks, and a one-action step cap.

The canary and payload policies run before tool dispatch. A request may be stopped before inference; its model fields then remain empty. Discuss why a phrase filter and an exact-canary detector are limited teaching controls, not production guarantees.

Same attacks & resume

Use the same run directory. Never edit the dataset between arms. Resume rejects source, dataset, model or budget changes.

Or finish both arms with --resume alone. Filters --owasp LLM01 and --scenario LLM01-A1 select canonical rows; the smoke gate still applies to live runs.

03SYSTEM MAP

  1. Untrusted input
  2. Prompt policy · instructions, not an enforced boundary
  3. Model
  4. JSON response · finding or refusal
  5. Application schema validation
  6. Findings + explicit failures

Read it: Follow the input into the model, then notice the separate validation stage. A valid shape is not proof of safety.

04WHAT TO NOTICE

Decision map

  1. ✓
    Valid outputInspect the findings; shape alone proves no safety.
  2. ◇
    RefusalRecord what the model declined.
  3. !
    Invalid JSONKeep the raw response and parse failure.
  4. !
    Schema errorJSON parsed; required fields or types failed.

Record output validity and model behavior separately; a refusal may also be valid JSON.

ENGINEER’S LENS

Schema compliance is not semantic correctness. A valid response can still be wrong or unsafe.
